## 2. 现有工具做什么

它通过某个研究主题的论文检索结果，汇总出现过的期刊及论文数量，并补充英文期刊的部分指标。当前没有提供输入期刊名或 ISSN 直接批量查询的入口。

工作流程：

1. Tkinter 界面读取检索词、检索位置、起始年份、ChromeDriver 所在目录和结果保存目录。
2. `wd_split_dou()` 把逗号分隔的检索词转换为精确检索或至少包含一个词的检索表达式。两个输入框同时填写时，仅采用第一个。
3. `BaiduXueshuAutomatic._init_browser()` 创建 Selenium Chrome 浏览器。
4. `run()` 拼接百度学术搜索 URL，逐页读取论文标题和详情链接。
5. Requests 获取论文详情 HTML，正则提取 `journal_title`。
6. 期刊名含汉字时归入中文期刊；包含大小写精确匹配的 `Conference` 时归入会议；其余归入英文期刊。
7. 对英文期刊，以期刊名向 LetPub 搜索接口发起 POST，解析第一段匹配表格中的 CiteScore、分区和审稿周期。
8. 按期刊汇总论文标题与链接，每处理一篇可保存的论文就重写结果文件。

默认设置：2018 年起，检索词位于标题，未填关键词时使用 `video+captioning`，页码循环为 0 到 999（最多 1000 页），每页的 `pn` 按 10 递增。未找到搜索结果或发现特定重复链接时提前停止。

输出文件名为 `result_时_分_秒.txt`，内容通常是 JSON，而非普通文本表格。顶层包括 `all_paper_num`、`English Journal`、`Chinese Journal` 和 `Conference`。每个期刊的值是一个混合列表：首项是“共N篇”，后续项是 `{论文标题: 论文链接}`。英文期刊的字典键还拼入了指标文字。

当前抓取字段：期刊名称、论文标题、论文链接、论文数量、CiteScore、未标明体系和年份的分区、审稿周期原文。没有实现影响因子、ISSN/eISSN、出版社、开放获取状态、费用、官网、指标年份或抓取来源记录；CiteScore 不能当作影响因子。

## 3. 代码中已经确认的问题

下列行号对应本次下载的 `cyd_v1_stable.py`，页面结构在目标网站的当前状态未验证。

| 问题 | 代码依据 | 对后续工具的影响 |
| --- | --- | --- |
| 使用旧版 Selenium 接口 | 40 行 `executable_path`；98、121 行 `find_*_by_xpath` | 需适配现代 Selenium 的 Service 和 By 定位接口；上游未锁定依赖版本 |
| 界面与抓取在同一线程 | 429 行按钮回调直接运行 `d.run()` | 长任务会阻塞界面，没有停止按钮、进度和可用的交互 |
| 页面解析脆弱 | 98–99 行绝对 XPath；142 行正则；264 行直接取匹配结果 `[0]` | 页面变化、验证码、空结果或错误页可能被误判为结束，也可能抛出异常 |
| 期刊身份匹配不足 | 249、264 行按名称查找并解析第一段结果 | 未验证完整名称或 ISSN，可能将相似期刊的指标关联到一起 |
| 分类规则过于简化 | 161 行汉字判定；202 行 `Conference` 判定 | 中文会议、其他会议命名和混合语言名称可能分类错误 |
| 缺少超时和有限重试 | 136、251 行请求未设 timeout；85–102、247–262 行循环 | 网络异常可能长时间阻塞或无限重复；错误提示不能证明真实原因是封禁 |
| 重复查询同一期刊 | LetPub 请求位于逐篇论文循环中 | 浪费请求和时间，同一期刊的指标变化还会拆分汇总键 |
| 用字符串排序数量 | 190–192、231–232 行按“共N篇”排序 | 离线复现显示“共9篇、共2篇、共10篇”，不是数值降序 |
| 指标嵌入期刊主键 | 277–284 行 | 缺少稳定标识，字段难以过滤、比较和导出 |
| 数据变量混用字典和字符串 | 194、234、314 行赋值为 JSON 字符串；104–109 行再次序列化 | 若上一页最后完成了序列化，下一页为空时会把 JSON 再包成字符串；复现后一次 `json.loads()` 得到 `str` 而非 `dict` |
| 重写结果不具原子性 | 315–317 行等 | 保存时中断可能破坏文件；没有可靠的续跑状态 |
| 没有完整去重机制 | 128–133 行仅比较一条重复链接 | 无法稳定处理跨页重复论文及期刊名称变体 |
| 正常提前结束被显示为异常 | 109 行返回 None；430–433 行只接受返回 0 | 搜索自然结束也可能显示“异常终止” |
| 浏览器没有显式清理 | 文件未调用 `quit()` | 结束或失败后可能残留浏览器进程 |
| 导入即产生副作用 | 326 行创建窗口；501 行联网读取图片；545 行 `mainloop()` | 不适合直接作为库复用，远程图片不可用也会影响启动 |

另外，期刊名称中 `: ` 后的部分会被截去（152–153 行），可能损失有用名称信息。CiteScore 的正则把小数点写为任意字符，且字符串中的 `\d` 在 Python 3.13 下产生 SyntaxWarning。输出文件名仅含时间，缺少日期和任务标识。

## 5. 作为新工具基础的建议

可复用的是“论文检索 → 提取期刊 → 补充指标 → 汇总导出”的业务流程、关键词输入思路，以及上游对数据来源的探索。实现层建议逐步拆开，避免继续将界面、HTTP 请求、解析和存储混在一个函数中。

优先顺序：

1. 明确首版入口：直接输入期刊名称/ISSN 批量查信息，或者继续按研究关键词发现期刊。两个入口可共享期刊查询模块。
2. 先做一个期刊数据源的小样本验证，记录原始页面、解析字段及失败类型，再确认真实可获得的字段。
3. 把期刊、论文、年度指标分开建模。至少保留原始名称、规范名称、ISSN/eISSN、指标值、指标年份、分区体系、来源 URL、抓取时间和查询状态；缺失与未匹配分开表示。
4. 补超时、有限重试、访问频率控制、期刊缓存、去重和原子保存，先形成可以独立运行的抓取核心。
5. 在核心稳定后增加界面、任务进度、取消操作和 CSV/Excel 导出。当前阶段尚未确定界面技术栈，也未实施重构。
